# 生鲜到货数仓排查

生鲜到货进不了数仓时，用本页逐笔查全阻断原因，采购员和商品档案员各自按清单补录/更正。
Flask + SQLite，Docker Compose 一键启动。

## 启动

```bash
# Docker（推荐）
docker compose up --build
# 打开 http://localhost:8000

# 本地开发
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
python wsgi.py          # 或 flask --app wsgi run
```

SQLite 文件默认在容器卷 `appdata`（`/data/app.db`），本地默认 `instance/triage.db`，可用环境变量 `APP_DB` 指定。

## 使用

首页一次提交为一个**批次**，三种 CSV 可任选组合（UTF-8，中英文表头均可）：

| 文件 | 列（中文表头） | 列（英文表头） |
| --- | --- | --- |
| 到货 | 编号,采购行号,扫码条码,UTC时刻 | id,po_line_no,barcode,ts_utc |
| 采购行 | 编号,约定条码 | id,barcode |
| 用码记录 | 编号,条码,商品,UTC开始,UTC结束 | id,barcode,product,start_utc,end_utc |

- 时刻为 ISO8601 UTC（如 `2026-11-10T00:00:00Z`；无时区按 UTC 处理）。
- **同类同号以本次上传为准**（按编号 upsert；同一文件内同号取最后一行）。
- **用码期含起点、不含终点** `[start, end)`。
- `sample_data/` 有三个示例文件，可直接上传体验。

阻断原因（逐笔查全，可叠加）：

| 原因 | 挂在 | 谁来修 |
| --- | --- | --- |
| 采购行缺失 | 采购行号 | 采购员补录采购行 |
| 条码不符（约定≠实扫） | **采购行号 + 条码两侧** | 采购员更正约定条码 |
| 到货时该码无归属 | 条码 | 档案员补录用码记录 |
| 一码对应多商品 | 条码 | 档案员更正用码期/商品 |

首页两栏清单（采购员按采购行号、档案员按条码）给出**待修项、受阻笔数、明细**；
条码不符一笔同时挂在两边。顶部可按到货编号查当前**放行/受阻**。
全部阻断解除才放行；更正数据也可能让已放行的记录退回。

## 实现要点

- **同批生效**：每批上传先整体解析校验，然后 `BEGIN IMMEDIATE` → 底表 upsert →
  关联到货回查（刷新 `blocks` 与 `arrival_status`）→ `COMMIT`。
  任一步失败整体 `ROLLBACK`，**保留上次结果**（含"一个文件合法、一个非法"的情况）。
- **增量回查**（更正只回查改动前后关联的到货）：
  - 到货行变动 → 重查本笔；
  - 采购行 X 变动 → 重查所有 `采购行号 = X` 的到货；
  - 用码记录变动 → 重查 `条码 ∈ {旧值, 新值}` 且到货时刻落在旧/新用码期内的到货。
  `arrival_status.checked_batch` 记录每笔最后被回查的批次，可据此验证回查范围。
- **清单直接取受阻笔数**：两侧清单是对 `blocks` 表 `GROUP BY reason, item_key` 的
  `COUNT(DISTINCT arrival_id)`，不从底表重算，与回查同事务生效。
- **放行状态落库**：`arrival_status.released = (该笔无任何阻断)`，与底表同批更新；
  更正引入新阻断时同事务退回。
- 评估逻辑见 `app/core.py:_reevaluate`；回查范围见 `_collect_affected`。

## 验证

```bash
pip install -r requirements-dev.txt
python -m pytest tests/ -q
```

`tests/test_flow.py` 11 项端到端用例（Flask test client，真实走批次事务）：

1. 四类阻断原因齐发、一笔多原因、条码不符同时挂两侧清单、受阻笔数核对；
2. 补录缺失采购行 → 阻断解除、清单同步、到货放行；
3. 补录用码记录 → 无归属解除、其余原因保留、仍受阻；
4. 缩短用码期 → 已放行记录退回；改回 → 重新放行；
5. 用码期边界：恰在起点有归属、恰在终点无归属；
6. 同批一好一坏两个文件 → 整批 400，合法文件也未入库，清单与放行状态保持上次结果；
7. 只改某条码用码期 → 仅关联到货 `checked_batch` 前进，其余不变（增量回查）；
8. 同类同号以本次上传为准（含文件内同号取最后一行），且可造成退回；
9. 英文表头可用；10. 空上传拒绝；11. 页面冒烟（首页两栏、明细页、到货页）。

另用 gunicorn（与镜像同一入口 `wsgi:app`）+ `sample_data/` 做过真实 HTTP 冒烟：
上传 → 补档 → 退回 → 失败批次，结果与测试一致。

## 缺项 / 边界说明

- 无登录与角色权限：两栏清单对所有人可见，未按采购员/档案员隔离操作权限。
- 只支持 upsert，**不支持删除**底表行；录错的行只能用同编号覆盖更正（如把用码期改到不覆盖任何到货）。
- 明细页未分页，单批次文件上限 16MB；超大文件未做流式解析。
- 同一到货在同一 (原因, 侧, 对象) 下只记一条阻断（主键去重），同一采购行号/条码的明细说明以单条为准。
- 用码记录"商品"为自由文本，未接商品主数据校验；一码多品按 DISTINCT 商品名判定。
- 并发以 SQLite 行级事务 + `busy_timeout` 兜底，适合部门级单实例；多实例水平扩展需换外部数据库。
